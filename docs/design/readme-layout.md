# GitHub Legends — README Layout

- **Version:** 0.1 · **Date:** 2026-10-20
- The exact structure of the generated block inside `README.md`, which format each part uses, and why.
- Hard rule (PRD INT-6): the generator writes **only** between `<!-- LEGENDS:START -->` and `<!-- LEGENDS:END -->`. Everything else in the README (the owner's intro, tech stack, real "🏆 Achievements", existing stat cards) is untouched.

## 1. What GitHub README rendering allows

| Capability | Status | Use in GitHub Legends |
| --- | --- | --- |
| Markdown (headings, lists, tables, links, emphasis, task lists, blockquotes) | ✔ | Dynamic text: quests, battle log, records, squad, summaries |
| HTML: `<p align>`, `<div align>`, `<a>`, `<img width height alt>`, `<picture>` + `<source media srcset>`, `<details>`/`<summary>`, `<sub>`, `<sup>`, `<br>`, `<table>` | ✔ | Layout, theming, collapsing |
| Inline `style`, `<style>`, `class`-based CSS | ✖ stripped | Not used |
| JavaScript, event handlers, `<iframe>`, forms, `<map>`/`<area>` | ✖ stripped | Not used |
| SVG via `<img>` / `<picture>` | ✔ rendered as an image: no scripts, no external fetches; internal CSS and animation work | All visual cards and the map |
| Inline `<svg>` in Markdown | ✖ not rendered | Not used |
| PNG / GIF | ✔ | **Not used in v1** (see §2) |
| `<source media="(prefers-color-scheme: …)">` | ✔ (documented by GitHub) | Dark and light variants (VD-02) |
| `<source media="(max-width: …)">` | **[verify]**: not documented | Not relied on; the layout is responsive through wrapping instead (§4) |
| Relative image paths | ✔ resolve to files in this repo | All assets |
| Task-list checkboxes `- [x]` in README | **[verify]** | Quest lists. Fallback: ☑ / ☐ characters. |

## 2. Format decision matrix

| Section (screen) | Markdown | Supported HTML | Generated SVG | PNG/GIF | External links | Rationale |
| --- | --- | --- | --- | --- | --- | --- |
| Section heading | ✔ `###` | — | — | — | — | Native, accessible, part of the GitHub outline |
| **Player lobby: player card** | — | `<a><picture>` | ✔ C-10 | — | — | Identity needs visual hierarchy and the avatar |
| **Player statistics: summary line** | ✔ C-11 | — | — | — | — | Text for screen readers, search and blocked images |
| **Rank progression: season card** | — | `<a><picture>` | ✔ C-20 | — | — | Crest and stars are visual by nature |
| **Hero collection / mastery** | — | `<a><picture>` | ✔ C-30 | — | — | Medallions and tiers need art |
| **Achievement gallery: medals strip** | — | `<a><picture>` | ✔ C-43 | — | — | Collection display |
| **Quest board** | ✔ task lists C-40/41/42 | `<sub>` | — | — | — | Changes daily; text is accessible, tiny and mobile-friendly |
| **World map** | ✔ region list C-51 | `<details>`, `<picture>` | ✔ C-50 | — | — | Visual journey + full text equivalent |
| **Battle history** | ✔ table C-46 | `<details>` | — | — | Links to public PRs and releases | Tabular, many rows |
| **Emblem system / equipment** | ✔ declared kit C-39 | `<details>`, `<picture>` | ✔ C-35/C-37 | — | — | Build slots are visual; declared kit is text |
| **Squad** | ✔ list C-48 | `<details>` | — | — | Profile links of allies | People, so text and links, no avatars |
| **Leaderboard (records)** | ✔ table C-47 | `<details>` | — | — | — | Tabular |
| **Season overview** | ✔ (in summary line and the season card header) | — | (card) | — | — | Covered by the season card; full archive on L1 |
| Footer | ✔ C-61 | `<sub>` | — | — | "How it works" (repo link) | Small print |

**PNG and GIF are not used in v1:** they are raster (blurry at 2× or scaled), heavy, have no theme switching and (for GIF) no reduced-motion support. A single **1280 × 640 PNG social preview** (the repository's Open Graph image, rendered from the player card SVG) is optional and lives outside the README.

**External services:** none for rendering (no third-party stat images). External links are limited to GitHub URLs (profiles, public PRs and releases). The owner's existing third-party stat cards stay outside the markers (Phase 00 D-10).

Rules for the template:

- Blank lines around Markdown inside `<details>` and `<p>` blocks (GitHub requires them for Markdown to render inside HTML).
- `<summary>` carries a status hint (current region, count) so collapsed sections still inform.
- No `height` attributes on images (preserves the aspect ratio when scaled).
- Sections disabled in config are omitted entirely, including their `<details>`.
- The stale banner (C-62) is inserted directly under the heading when health is `stale` or `failed-run`.

## 4. Responsive behaviour (no media queries)

| Mechanism | Effect |
| --- | --- |
| **Card width 400 px**, inline images inside one `<p align="center">` | Desktop (column ≥ 804 px): two cards side by side. Narrower columns (tablet, phone): cards **wrap** into one column automatically. |
| Browsers scale images down to the container (`max-width: 100%` in GitHub CSS) | On a 360 px phone column a 400 px card renders at 0.9×; essential text (≥ 11 px) stays ≥ 9.9 px |
| Map portrait 420 × 820 inside `<details>` | Same image on all devices; collapsed by default |
| Markdown tables limited to 3 columns | Avoids horizontal scrolling on phones |
| Pairs always have equal height (250) | Clean rows on desktop; no ragged wrap |

**[verify] in the engineering spike:** the exact README column width on github.com at common viewports (1280, 1440, 1012) when logged in and logged out, to confirm two 400 px cards fit side by side. A Phase 03 attempt to measure this from the sandbox failed (GitHub's stylesheets did not load), so the number is not assumed. The fallback is safe: if they don't fit, the cards stack.

**Validated in Phase 03:** mockups rendered with Chromium in a README-like column at 912 px and 375 px wide. Desktop shows the side-by-side rows; mobile shows stacked cards, a legible map and no horizontal scroll.

## 5. Asset paths and caching

```
assets/legends/
  dark/  player-card.svg  season-card.svg  hero-lineup.svg  medals-strip.svg  world-map.svg  build.svg  emblems.svg
  light/ (same names)
docs/legends/…            generated Markdown pages (information-architecture.md §2)
```

- Images are referenced by **relative path** and served from the repository, so they refresh when the generator commits. No proxy cache delay like external images (Phase 00 risks §2).
- Deterministic rendering: unchanged state gives byte-identical SVGs, so no commit (PRD SYS-16).

## 6. Size budget (README)

| Part | Budget |
| --- | --- |
| Generated Markdown block | < 15 KB (PRD) |
| Visible above-the-fold images | 4 SVGs × ≤ 40 KB per theme |
| Map | ≤ 100 KB per theme |
| Total generated assets | ≤ 1 MB |

## 7. Accessibility checklist (per run, automated where possible)

1. Every `<img>` has non-empty `alt` equal to the SVG's `<desc>` (≤ 600 characters).
2. Level, rank, season and BP appear as plain text (summary line).
3. Quest progress is text (task lists), not only bars.
4. No essential information is conveyed by colour alone (words and patterns accompany colours).
5. Contrast tokens meet WCAG AA for text in both themes (visual-direction §3).
6. Headings are real Markdown headings (`###`, `####`), in order.
7. Animations are off by default; any animation respects `prefers-reduced-motion`.
